# Quel modèle pour quelle phase

*« Opus 5 est-il meilleur que Fable 5 ? »*

## Le propos

Quatre modèles en deux mois. Son vrai sujet n'est pas lequel est « le
meilleur », c'est qu'on n'a plus le temps de s'installer dans un outil avant que
le suivant sorte.

Il décortique l'annonce de prix, teste les deux sur son propre code, et regarde
un banc d'essai indépendant plutôt que les chiffres du constructeur — c'est le
réflexe à retenir.

**Son verdict : Opus par défaut, Fable en joker.**

## Ce que ça vaut pour nous

La partie utile est le chapitre « quel modèle pour quelle phase de projet ». La
logique, indépendamment des noms du moment :

| Phase | Ce qu'on veut |
|---|---|
| explorer, réfléchir, décider | le modèle le plus solide, on paie pour la qualité du raisonnement |
| écrire du code répétitif | un modèle rapide suffit |
| relire, auditer | le modèle solide à nouveau, et si possible un second pour croiser |

C'est là que la commande `/effort` de
[[Les-15-nouvelles-commandes-Claude-Code]] prend son sens : régler le curseur
selon la phase plutôt que de tout faire au maximum.

**Attention à la péremption.** Cette vidéo a six jours, et sur ce sujet six
jours c'est déjà vieux. Ce qui reste vrai, c'est le raisonnement — pas les noms
de modèles.
